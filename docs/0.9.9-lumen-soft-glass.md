# Lumen soft dark glass — local 0.9.9

Implemented, packaged, tested and installed locally; current 0.9.9, rollback 0.9.8. No public release or push. Shane requested soft dark glass with a slight blue cast after rejecting both the white treatment and the uninstalled petrol-blue direction.

The [research and execution record](superpowers/plans/2026-11-02-lumen-soft-glass.md) connects Microsoft Acrylic/Fluent and Apple materials/Liquid Glass guidance to the existing Qt implementation. Two specialist reviews covered visual material principles and native Windows/Qt feasibility.

## Changed

- Neutral charcoal foundation with restrained steel-blue focus, selection and primary-action accents. The title bar now matches this dark finish and retains normal Windows controls.
- A quieter shared moving reflection, a single fine pane contour, shallow light falloff on raised buttons and recessed dark input wells. Pane tint varies subtly without a saturated blue or white wash. Existing layout, spacing, feature positions and hit areas remain.
- Pale, muted semantic icon colours replace the old dark glyphs. A separate darker progress-bar fill preserves readable download percentages; review caught both contrast issues before packaging.
- Real clear desktop translucency remains available for Lumen. Reduced transparency, increased contrast and Windows accessibility/transparency preferences retain their existing opaque fallback. Menus use the readable internal material. The mapping canvas/projector remain opaque.

Settings -> Appearance -> Theme motion retains Pause, Light and 0.2–2.4x speed. This installation remains at 1.8x, Light 100%, playing. Other themes are retained.

## Evidence

Artifacts are bounded under `out/lumen-petrol` (the directory name reflects the abandoned initial experiment):

- `checks-studiothemes.json`: studio 249 assertions, all-theme suite and scaled studio 249 assertions all exit 0. Checks cover layout/widget identity, motion/pause, accessibility, scene/Undo preservation and opaque output.
- `installed-rollback.json`: actual launcher 0.9.9 -> 0.9.8 -> 0.9.9 reopens the synthetic saved mapping/media successfully.
- `normal-close.json`: the normal installed editor, with the user's original mapping open, exited through its native Close button and released its runtime lock. It was then reopened through the normal launcher.
- `final-integrity.json`: all 17 protected file hashes match, 95 manifest entries in each current/rollback runtime match, and the installed editor equals the built executable. Combined measured project storage is about 1.15 GB against the 1.9 GB cap.
- Actual native inspection confirms readable native caption, revised material hierarchy and retained right-click Delete/Connect actions. `installed-soft-glass.png` is the installed window. The separate coloured test window is only a transparency check, not an app wallpaper asset.

An old hidden 0.9.8 process still held the installation lock. Its clean saved mapping and all protected hashes were verified before stopping it. The first update was refused because its stale lock file remained; the launcher kept the selected runtime unchanged and discarded that staging session. The dead owner's lock was moved to `stale-runtime-lock.txt`, the unchanged build was restaged, and installation plus rollback succeeded. No launcher recovery fix is claimed by this visual increment.

## Remaining boundary

This is clear semi-gloss with a revised soft-dark material treatment. **Native frosted Acrylic blur and Apple's optical refraction are not implemented.** The documented Windows Acrylic configurations tested in an isolated Qt/OpenGL window returned success but produced opaque grey/black here; they were excluded. Do not describe this as a complete reproduction of Windows/Apple glass. No screenshot capture, copied Windows wallpaper, new renderer/framework or project-format migration was added. User visual acceptance and physical projector appearance remain separate.
