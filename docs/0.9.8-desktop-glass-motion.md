# 0.9.8 — Lumen desktop glass and faster motion

Implemented, packaged, checked and installed locally through the normal launcher as 0.9.8. Previous runtime: 0.9.7. No public release or push.

- Lumen Atelier's editor chrome now uses actual per-pixel desktop translucency on supported Windows 11 systems. Windows and wallpaper behind the app remain visible through its glossy white panels. The OpenGL mapping canvas and projector remain opaque and unchanged.
- Stronger translucent text backing, darker secondary ink, readable controls and native caption rendering keep the real see-through interface usable. Normal title-bar buttons, resize, snap and maximize remain native. No controls were moved or removed.
- Settings → Appearance → Theme motion now permits **0.2×–2.4×**, with the existing Pause and Light controls. Existing saved speeds and reset defaults remain valid. Pausing stops app reflections; it cannot pause another application visible behind the glass.
- Reduced transparency, increased contrast and Windows transparency/high-contrast preferences disable native translucency. Other interface themes retain their previous materials. Menus/dialogs retain their readable existing material.

This is **clear semi-gloss desktop translucency**, not a claim of blurred Acrylic or optical refraction of desktop objects. The isolated Desktop Acrylic experiment returned success but rendered opaque grey on this host. A Windows Composition host brush obscured Qt content. Those experimental routes are excluded. No screenshot capture, desktop pixel readback, copied wallpaper or extra runtime framework is used by the shipped adapter.

## Engineering and verification

`src/desktop-glass.cpp` prepares the existing Qt editor's alpha surface before HWND creation. Zero extended-frame margins preserve the native caption; `DwmEnableBlurBehindWindow` enables alpha composition in the client area. Despite that API's name, modern Windows does not supply its old Aero blur. The 24H2 redirection-bitmap alpha override stays disabled. Extending glass across the entire frame hid the caption in the full-app visual check; that route is excluded. Lumen's light caption mode is restored when leaving the theme. Theme switches keep the same HWND and Qt widgets. A separate native composition/setting-change handler refreshes the adapter; failed native setup restores the opaque fallback. Rendering only paints a translucent veil and shared animated reflection over that surface.

Relevant references: [DWM attributes](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute), [client alpha and modern Windows blur limitation](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/nf-dwmapi-dwmenableblurbehindwindow), [Qt OpenGL composition and transparency](https://doc.qt.io/qt-6.10/qopenglwidget.html#limitations-and-other-considerations).

The initial launcher exit regression exposed a pre-existing OpenGL cleanup lifetime defect: the context's direct destruction callback could call `Canvas::cleanup` after Canvas's GL members had been destroyed. Cleanup now disconnects that callback first. On application quit, native backdrop callbacks are detached, chrome motion stops and both windows hide before destruction. Existing save prompts remain unchanged. Three consecutive focused Lumen saved-project smoke checks completed with exit code 0 after the fix; final packaged checks include that corrected binary.
